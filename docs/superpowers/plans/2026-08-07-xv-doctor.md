# `xv doctor` Configuration Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a top-level `xv doctor` command that runs despite a broken global config, automatically repairs deterministic schema omissions after creating an exact private backup, and reports unresolved errors with exit code 3.

**Architecture:** A focused `config::doctor` engine reads and repairs an explicit path and returns a structured report; a thin CLI module renders that report. `main::run` short-circuits `Commands::Doctor` before ordinary config loading, while shared filesystem helpers provide no-follow reads and exclusive private backup creation.

**Tech Stack:** Rust 2021, clap 4, Tokio, serde/serde_json, toml 0.8, toml_edit 0.22, chrono 0.4, tempfile, existing `CrosstacheError` and atomic-write helpers.

## Global Constraints

- Scope is only the global `xv.conf` returned by `Config::get_config_path()`; do not inspect `.xv.toml`, credentials remotely, network access, or backend service health.
- Repairs are automatic and only deterministic: missing required current-schema fields and reviewed legacy-key mappings; never guess malformed values, credentials, or backend selection.
- Create a timestamped sibling backup containing the exact original bytes before every config rewrite; never overwrite an existing backup.
- Preserve TOML comments, formatting, unknown keys, and valid user values.
- A missing config is healthy and must not create a file.
- Exit `0` for missing, healthy, or fully repaired config; exit `3` when unresolved problems remain.
- Do not expose configuration values in diagnostics.
- Preserve the user's pre-existing `package-lock.json` modification and do not stage it.

- Create `src/config/doctor.rs`: report types, format detection, deterministic schema repair, validation, backup, atomic replacement, and unit tests.
- Create `src/cli/doctor_ops.rs`: human-readable report rendering and conversion of unresolved issues to `CrosstacheError::ConfigError`.
- Modify `src/config/mod.rs`: expose the new doctor module.
